# 项目文件规划

根据实际任务和项目现状确定文件位置。用户明确指定的结构优先；以下名称与树形结构只是示例，不要求预先创建。

## 按阶段聚合

有数据准备与多个实验阶段的项目，可以按以下方式组织：代码入口与对应数据、结果和图位于同一阶段目录。

```text
proj/                              # 项目名称按具体用途取简称
├── README.md                      # 按需维护
├── data/                          # 数据获取、理解与公共预处理
│   ├── raw/                       # 原始材料，保持来源与原样
│   ├── pro/                       # 供多个阶段使用的处理结果
│   ├── fig/                       # 数据理解或预处理相关的图
│   ├── pre.ipynb                  # 数据准备入口
│   └── README.md                  # 按需维护
└── exp/
    ├── README.md                  # 按需维护
    ├── 01_feat/                   # 一个有明确用途的实验阶段
    │   ├── feat.ipynb             # 该阶段的入口代码
    │   ├── data/                  # 本阶段专用数据或必要中间结果
    │   ├── res/                   # 指标、预测结果、模型等
    │   ├── fig/                   # 本阶段产出的图
    │   └── README.md              # 按需维护
    └── 02_win/                    # 仅在确有另一阶段时创建
        └── ...
```

- 只创建实际需要的阶段和子目录；单项任务无需强行建立 `exp/` 或编号。阶段专用文件放在该阶段，共享数据从公共位置引用；确需副本时注明用途。
- 数据准备代码与相关数据、图片放在 `data/`，实验代码与本阶段的 `data/`、`res/`、`fig/` 放在对应实验目录。跨阶段汇总产物放在职责明确的位置，不复制整套目录。
- 项目、目录和文件优先使用有明确含义的简短名称或常用缩写；目录编号只在有助于理解顺序时使用。自编代码文件名不得用 `run` 表示运行入口，不区分大小写。原始数据、标准配置和第三方文件保留原名，不因示例中的拼写而重命名。

## 在现有项目中落地

先查看实际结构、入口与项目约定。已有目录如 `experiments/`、`src/`、`outputs/` 和已有说明可沿用；只为本次任务做必要调整，不整体重排。已有自编代码名称不符合要求时，仅在本次范围内、安全且能修复引用时改名；不能安全改名时保留并说明。已有科研脚本不整体迁移；本次需要的自编科研分析逻辑直接写入 notebook，不能仅包装原脚本。

确需移动或清理时先核对文件用途、引用和运行依赖；仅处理获准范围，同步修正实际读写路径。不能确认安全时保留并说明。

## 路径与说明

- 依据实际启动位置解析路径，优先使用相对项目路径；找不到目标时明确报错，不在错误位置静默创建目录。需要时说明启动方式和输出位置。
- 复用已有说明；只有任务需要或文件用途难以理解时才创建或更新 README，不生成无内容的说明或重复记录。
- 不预建空目录，也不为了展示结构制造数据、图、结果、样例代码或多份相同文件。
