# Pre-Rule：项目规范

根据当前任务和项目实际情况规划文件，无需额外输入文件或固定模板。用户本次明确要求和更高优先级指令优先。

## 文件组织

- 开始前查看已有目录、入口、数据来源和约定，确定本次产物的归属及读写路径。不为套用示例整体搬迁或改名；涉及已有数据的迁移须在任务范围内核对依赖并更新引用，无法安全迁移时沿用原位置并说明。
- 原始数据、预处理数据，以及数据检查、清洗、转换、特征生成和可视化的 notebook、图片集中放在项目的 `data/` 下；不要把数据准备流程放入 `exp/`。可按需用 `data/raw/` 和 `data/pre/` 区分数据，或沿用已有清晰的分类，不强制新建子目录。原始数据保持原样；外部或只读数据直接引用并说明，不为凑目录复制。
- 实验 notebook 和实验结果放在 `exp/` 下；同一实验的代码、指标表、预测表、模型和图表应在同一个实验目录或其子目录内就近存放。实验直接读取 `data/` 中的原始或预处理数据，不在 `exp/` 复制输入或重新实现数据准备流程。后续实验需要已有结果时直接引用原路径，不复制到 `data/` 或其他实验目录。
- 根据实际规模组织目录：单个实验可以直接使用 `exp/` 作为实验目录；多个实验按主题区分，可按需分别建目录，避免结果混淆。结果和图表可以与 notebook 并列，也可按需建立 `res/`、`fig/` 等子目录；不强制阶段编号、固定层级或预建目录。
- 已有项目中数据处理与实验混放时，若属于本次任务且能安全更新依赖，将相关处理逻辑整理至 `data/` 下的 notebook，并更新读取路径、核对结果；不能安全迁移时保留并说明，不为套用结构整体搬迁。
- 项目自有内容的每个目录都维护一份 `readme.md`，包括项目根、数据及其子目录、实验阶段和结果、图片子目录。简要说明目录作用、现有关键文件或子目录及必要的输入输出关系，内容变化时同步更新；已有 `README.md` 等大小写不同的同一说明文件则沿用，不重复创建。`.git`、依赖、缓存、第三方及外部只读目录不写入。
- 只创建当前任务需要的文件和目录，不预建空目录、占位文件、演示数据、多余脚本、重复结果、计划、日志或报告；每个实际存在的项目内容目录按上述要求维护说明。
- 项目迭代时，确认目标属于本次任务且用途相同后，默认在原路径直接更新或覆盖已有 notebook、处理后数据、结果、图片和说明，不必为常规覆盖重复询问。按需重新运行受影响的步骤，使代码、数据、图片和说明一致；无法重新生成时说明哪些产物未更新。
- 不为日常修改生成备份副本、带日期或版本号的副本、版本目录、压缩包或归档。用户要求保留、项目有明确保留约定，或不同实验条件及对照需要同时比较时，再按用途分别保存。
- 项目、目录和文件采用简洁、易理解的英文单词或常用缩写，如 `data`、`exp`、`fig`、`feat`；仅在有助于理解顺序时给阶段编号。标准配置、原始材料和第三方文件沿用规定或原有名称。
- 自编代码文件名不得以 `run` 命名，也不得将 `run` 用作表示运行入口的前缀、后缀或独立词段，不区分大小写；根据职责命名，如 `pre.ipynb`、`feat.ipynb`。已有文件仅在本次任务范围内且能安全更新引用时改名，否则保留并说明。
- 明确 notebook 的启动位置和输入、输出路径，避免在错误位置静默创建文件；按文件类型或清单读取数据，避免将 `readme.md` 当作数据。原始数据保持原样，处理结果另存；移动或清理前核对用途与依赖并更新引用，不能确认安全时保留并说明。

## 实验和代码

- 围绕当前研究问题确定各阶段的目的、输入、处理或实验方法和结果判断方式；按实际依赖推进，必要时选择有意义的基准、对照或比较。根据真实结果决定后续工作，不为凑步骤增加无关实验。
- 所有自编科研和分析逻辑必须直接写在所属阶段的 `.ipynb` 代码单元中，包括数据处理、分析和科研绘图；不得用自编脚本、命令行内联计算或 notebook 包装外部脚本来绕过。第三方库、文件管理及 notebook 执行工具可正常使用；非科研分析的工程代码按项目需要组织。已有科研脚本无需整体迁移，用户本次明确指定其他形式时遵从。
- 代码按实际处理和实验步骤直接、顺序地实现，保持简洁易读；不使用难以直观看懂的抽象逻辑、通用框架、无必要的封装、深层嵌套或冗长的链式表达。确需复用时，可在 notebook 中定义简短、职责明确的函数。
- 变量使用表意清楚的英文单词或常用简称，如 `data`、`feat`、`pred`、`err`；同一含义保持命名一致，避免含义不明的自造缩写和单字母名称，常用数学符号及循环索引除外。
- 在所属 notebook 中用简洁 Markdown 说明目的、数据来源、关键方法或参数、结果和必要局限，使代码、结果与解释对应。未执行的实验及其原因要明确标注，不编造数据或结论。
- 各单元只展示该步骤需要的主要内容，如数据维度、少量记录预览、关键指标和必要图表；无需展示结果的单元保持无输出。不要在 notebook 中输出完整大表、长数组、冗长模型摘要、对象表示、重复日志或占据大量空间的进度条。
- 限制预览行列，按需关闭冗余日志和进度条；绘图后显式展示图片，避免出现 `<Axes: ...>` 等无意义对象文本或重复图片。交付前检查 notebook 保存的输出，清理无意义的历史噪声；需要保存的完整结果按约定路径存放，预览应标明。不得为了简洁掩盖执行错误、影响结果的重要警告或更改数据。

## 绘图规范

- 仅在任务需要时根据实际数据绘图。每张图突出一个主要问题或比较，优先使用易读的二维折线图、散点图、柱状图或直方图；简单图表足以表达时，不增加三维、复杂渐变、繁杂装饰或无关指标。
- 让非本领域人员也能看懂主要趋势：标明比较对象、工况、坐标变量及单位，解释必要缩写；图例、标题或简短图注应帮助理解，不遮挡数据。默认中文标注，用户要求或投稿时按实际需要调整。
- 优先白底、深色坐标轴与清晰刻度，去除或淡化无必要的网格；字体和线条在实际展示尺寸下清楚可读。使用少量容易区分的颜色，同一方法在各图中保持一致，并结合线型或空心／实心标记区分；两组对比可参考蓝色 `#3A6EA5` 与橙红色 `#C9563C`，不强制固定配色。
- 多工况或多指标确需分图时，按行列有规律排列，标明各子图的变量与工况，必要时使用共享图例；同类比较尽量统一单位和坐标范围，范围不同时明确标出，避免误导。不得为美观删去或掩盖重要数据；必要的聚合、平滑或截取应说明。
- 图表的数据来源及绘图过程应可通过所属 notebook 追溯。数据检查和准备的图片放在 `data/`，实验图表放在对应实验目录内；可按需建立图片子目录。默认导出高质量 JPG，投稿、矢量、无损或用户指定的格式按实际需要调整。导出后按实际展示尺寸检查文字、图例和曲线是否清楚且未被裁切。

视觉参考：[Tao 等（2024），Fig. 2b、4b–d](https://www.nature.com/articles/s41467-024-54454-0) 和 [Che 等（2026），Fig. 3g–h、6](https://www.nature.com/articles/s41467-025-67565-z) 中的对比与分组方式，以及多工况曲线的整齐布局；具体图表以清晰易懂为先，无需复制论文的复杂组合或额外读取参考文件。

## 交付说明

完成时简要说明主要文件或目录的作用及数据流向，包括 notebook 入口、原始和处理后数据、结果与图片的位置；结合实际结果解释重要图表和发现，并说明未执行的步骤或限制。

## 组织示例

以下仅说明文件归属，不要求创建其中的文件或子目录：数据处理可使用 `data/pre.ipynb`，数据可按需放在 `data/raw/`、`data/pre/`，查看数据的图片可放在 `data/` 或其子目录。单个实验可在 `exp/` 内放置 notebook、结果和图表；多个实验可分别使用 `exp/` 下的实验目录。每个实际存在的项目自有内容目录按上述要求维护说明。
