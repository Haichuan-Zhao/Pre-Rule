# Pre-Rule：项目文件规范

根据用户当前任务和项目实际情况规划文件，不要求额外的输入文件或固定模板。用户本次明确要求和更高优先级指令优先。涉及项目文件组织时读取 [项目文件规划](references/project-layout.md)；涉及图片文件的保存时读取 [图片文件管理](references/figures.md)。

## 文件组织

- 开始前查看项目已有目录、相关入口和约定；先确定本次产物归属与实际读写路径，再创建或修改。已有结构合适时沿用，不为套用示例整体搬迁或改名。
- 默认按工作阶段就近组织：数据准备与各实验有明确位置；每个阶段的代码入口与其专用数据、结果、图片和必要说明放在同一阶段目录，数据、结果和图片使用该目录内的子目录。共享材料优先保留一个来源并引用；确需冻结或离线副本时说明用途。
- 只创建当前任务实际需要的文件和目录。不自动生成空目录、占位文件、演示数据、多余脚本、重复结果、计划、日志或报告；确有用途或用户要求时再创建。说明文档按需维护，不机械地为每个文件夹创建 README。
- 项目、目录和文件使用简洁、表意清楚的名称，优先采用可理解的英文单词或常用缩写，如 `data`、`exp`、`fig`、`feat`；阶段可按需要命名为 `01_feat`、`02_win`。不要使用难以辨认的缩写；标准配置文件、原始材料及第三方文件保留规定或原有名称。
- 自编代码文件名不得以 `run` 命名，也不得将 `run` 用作表示运行入口的前缀、后缀或独立词段，不区分大小写；根据实际职责命名，如 `pre.ipynb`、`feat.ipynb`、`win.ipynb`。遇到已有不符合的自编代码文件，仅在本次任务范围内、可以安全更新引用时改名；不能安全改动时保留并说明。
- 路径应明确相对于项目根或获准的外部位置，并与实际启动位置一致，避免输出散落到错误目录。
- 保留用户原始材料和仍在使用的文件。移动、覆盖或清理前核对依赖和保留用途，并同步相关路径与引用；无法确认安全时保留并说明。

## 代码和图片

- 所有自编科研和分析逻辑必须直接写在所属阶段的 `.ipynb` 代码单元中，包括数据处理、分析和科研绘图。不得用自编脚本、命令行内联计算或 notebook 包装外部脚本来绕过；第三方库、文件管理和 notebook 执行工具可正常使用。非科研分析的工程代码按项目需要组织；用户本次明确指定其他形式时遵从。
- 仅在任务需要时生成图片，并放入所属阶段的 `fig/` 或已有等效目录。默认中文标注、高质量 JPG；投稿、矢量、无损或用户明确指定的交付格式按实际要求调整。
